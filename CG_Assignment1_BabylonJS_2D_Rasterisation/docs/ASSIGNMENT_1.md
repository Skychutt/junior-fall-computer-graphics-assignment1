# Computer Graphics — Assignment 1
## 2D Rasterisation: Lines, Triangles and Interpolation

### Purpose

This is the introductory practical assignment for the Computer Graphics module. You will build a small **software rasteriser in JavaScript**, displayed through Babylon.js.

The purpose is **not** to learn Babylon.js itself. A complete browser/Babylon.js environment is provided so that you can concentrate on the computer graphics algorithms:

1. **Explicit line representation** — easiest to understand.
2. **Implicit / half-plane representation** — convenient for rasterisation.
3. **Barycentric coordinates** — useful for triangle coverage and interpolation.

You will finish by producing a 2D scene containing a house, using your own rasterisation functions rather than Babylon.js line/triangle drawing primitives.

## Learning outcomes

After completing this assignment, you should be able to:

- explain the difference between vector geometry and rasterisation;
- convert geometric primitives into discrete pixels;
- implement a line rasteriser using the explicit equation `y = mx + b`;
- explain why the explicit form needs special handling for vertical lines;
- implement line rasterisation using an implicit / half-plane equation;
- determine whether a pixel lies inside a triangle using edge functions;
- calculate barycentric coordinates of a point with respect to a triangle;
- use barycentric weights to interpolate vertex colours;
- explain the relationship between line/triangle equations and rasterisation;
- distinguish **geometry** from the **pixels generated from that geometry**.

# 3. Important distinction: geometry vs rasterisation

For example, a mathematical line can be described as:

\[
y = mx+b
\]

but the display consists of discrete pixels.

Your algorithm therefore has to answer questions such as:

> Which pixels should be turned on to represent this line?

Similarly, a mathematical triangle is continuous, but the framebuffer is a finite grid:

```text
continuous triangle
        ↓
   rasterisation
        ↓
discrete covered pixels
```

# 4. Part A — Explicit line rasterisation

Implement:

```javascript
drawLineExplicit(x0, y0, x1, y1, color)
```

using the explicit line equation:

\[
y=mx+b
\]

where:

\[
m=\frac{y_1-y_0}{x_1-x_0}
\]

and

\[
b=y_0-mx_0
\]

### Requirements

Your implementation should:

1. determine the direction in which the line is traversed;
2. calculate the corresponding `y` value for each sampled `x`;
3. round/map the continuous coordinate to a pixel;
4. write the pixel using the supplied framebuffer function.

### Important limitation

Explain and handle the case:

\[
x_1=x_0
\]

because the slope becomes undefined.

You should explicitly discuss why the explicit representation is:

> **easy to understand, but inconvenient for some orientations.**

### Required demonstration

Display at least:

- a shallow line;
- a steep line;
- a horizontal line;
- a vertical line;
- a diagonal line.

# 5. Part B — Implicit / half-plane line rasterisation

Represent a line using:

\[
F(x,y)=Ax+By+C
\]

For a line through \(P_0=(x_0,y_0)\) and \(P_1=(x_1,y_1)\), one possible form is:

\[
A=y_0-y_1
\]

\[
B=x_1-x_0
\]

\[
C=x_0y_1-x_1y_0
\]

A point is on the line when:

\[
F(x,y)=0
\]

The sign of \(F(x,y)\) tells you which side of the line the point lies on.

Implement:

```javascript
drawLineImplicit(x0, y0, x1, y1, color)
```

### Requirements

For each candidate pixel:

1. evaluate the implicit line function;
2. determine how close the pixel is to the line;
3. decide whether the pixel should be drawn.

You may choose a small tolerance around the line.

### Required comparison

Your report must compare the explicit and implicit approaches in terms of:

- mathematical representation;
- handling of vertical lines;
- implementation complexity;
- suitability for rasterisation.

# 6. Part C — Triangle rasterisation using half-planes

A triangle can be represented by three edge functions.

For an oriented edge \(A\rightarrow B\):

\[
E_{AB}(P)=
(B_x-A_x)(P_y-A_y)
-
(B_y-A_y)(P_x-A_x)
\]

For a consistently oriented triangle, a point is inside when it lies on the correct side of all three edges.

Implement:

```javascript
fillTriangleHalfPlane(A, B, C, color)
```

### Requirements

Your algorithm must:

1. calculate a screen-space bounding box around the triangle;
2. examine pixels inside the bounding box;
3. evaluate the three edge functions;
4. determine whether each pixel is inside;
5. write covered pixels to the framebuffer.

Do not call Babylon.js triangle drawing functions.

### Why this is important

This is a simplified form of the idea used by hardware rasterisers:

```text
triangle
   ↓
edge equations
   ↓
pixel coverage tests
   ↓
fragments/pixels
```

# 7. Part D — Barycentric coordinates

For triangle vertices \(A,B,C\), a point \(P\) can be expressed as:

\[
P=\alpha A+\beta B+\gamma C
\]

with:

\[
\alpha+\beta+\gamma=1
\]

The values \(\alpha,\beta,\gamma\) are the **barycentric coordinates** of \(P\).

Implement:

```javascript
barycentric(P, A, B, C)
```

returning:

```javascript
{
    alpha: ...,
    beta: ...,
    gamma: ...
}
```

### Use barycentric coordinates for colour interpolation

Give each triangle vertex a different colour:

```text
A = red
B = green
C = blue
```

For a point \(P\):

\[
C(P)=
\alpha C_A+
\beta C_B+
\gamma C_C
\]

Implement:

```javascript
fillTriangleBarycentric(A, B, C, colorA, colorB, colorC)
```

The result should show a smooth colour transition across the triangle.
